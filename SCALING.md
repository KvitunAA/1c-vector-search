# Подключение команды к MCP-серверу на SERVER_HOST

Как выдать доступ к `1c-vector-search` коллегам в Cursor и Codex. Про устройство самого
SSH-подключения — [SSH_REMOTE.md](SSH_REMOTE.md).

## Что уже проверено

| Проверка | Результат |
|---|---|
| Одновременные сессии под одной учёткой | 4 процесса MCP в один момент, все ответили |
| Память на одну сессию | ~250 МБ |
| Ресурсы сервера | 64 ГБ RAM (свободно ~56), 64 логических ядра |
| Лимиты `sshd_config` | `MaxSessions` / `MaxStartups` не заданы |

Каждое подключение — отдельная SSH-сессия и отдельный процесс. Общая учётная запись очереди
не создаёт. Умолчания `MaxSessions 10` и `MaxStartups 10:30:100` считают не пользователей:
первое — каналы внутри одного TCP-соединения, второе — незавершённые аутентификации. У каждого
клиента своё соединение и мгновенная авторизация по ключу, поэтому ни то, ни другое не ограничивает
число людей. При ~250 МБ на сессию десять человек — это около 2.5 ГБ.

Общий ресурс ровно один — **LM Studio**: модель одна на всех, параллельные запросы на эмбеддинги
встают в очередь. Это влияет на скорость поиска, но не приводит к отказу. Графовые инструменты
эмбеддингов не требуют и работают всегда.

## Часть 1. Настройка сервера (один раз, администратором)

### 1.1. Учётная запись

Доступ выдаётся под **отдельной непривилегированной** учёткой. Не раздавайте админскую:
SSH даёт полноценный shell, а не только MCP.

**Локальная или доменная?** Даже если сервер введён в домен, **достаточно локальной** —
при условии, что выгрузка 1С и базы лежат на его собственном диске (`CONFIG_PATH` — не UNC-путь).
Вход идёт по ключу, а не по паролю или Kerberos, поэтому домен в аутентификации не участвует.

Доменная учётка здесь не даёт того, ради чего её обычно берут: при входе по SSH-ключу Windows
выдаёт токен **без сетевых учётных данных** (S4U-логон), поэтому доступа к сетевым шарам не будет
и у доменной. Зато локальная ограничивает радиус поражения при утечке ключа этим сервером и не
зависит от доменных политик — истечения пароля и блокировок, которые положат доступ сразу всей команде.

Доменная оправдана, если этого требует ИБ (централизованное отключение в AD). Если базы или
выгрузка когда-нибудь переедут на сетевой шар — смены типа учётки не хватит: придётся отказаться
от входа по ключу либо настраивать делегирование.

Скрипт `add_mcp_user_key.ps1` работает с обоими вариантами: для доменной передавайте
`-Account "DOMAIN\mcp-user"`. Каталог профиля он определяет по SID через реестр, а не собирает из имени.

```powershell
# PowerShell от имени администратора на SERVER_HOST
$pw = Read-Host "Пароль для mcp-user" -AsSecureString
New-LocalUser -Name mcp-user -Password $pw -FullName "MCP 1c-vector-search" -PasswordNeverExpires
Add-LocalGroupMember -Group "Пользователи" -Member mcp-user   # англ. система: "Users"
```

Затем **однократно войдите под ней**, иначе Windows не создаст профиль и класть
`authorized_keys` будет некуда:

```powershell
runas /user:mcp-user cmd
```
Окно можно сразу закрыть — профиль `C:\Users\mcp-user` уже создан.

### 1.2. Права на файлы

```powershell
# Проект: чтение + запись (сервер пишет mcp_server.log, SQLite создаёт временные файлы)
icacls "C:\path\to\1c-vector-search" /grant "mcp-user:(OI)(CI)M" /T

# Выгрузка конфигурации: только чтение (нужна для find_1c_method_usage и путей в выдаче)
icacls "C:\path\to\1c\config\dump" /grant "mcp-user:(OI)(CI)RX" /T
```

Права на запись в каталог проекта нужны не для изменения баз, а для служебных файлов. Если
хотите жёстче — выдайте `M` только на `projects\ERP` и на файл лога, а на корень оставьте `RX`.

### 1.3. Ключ каждого коллеги

Коллега присылает **публичный** ключ (файл `.pub`, одна строка). Приватный не передаётся никогда.

```powershell
powershell -ExecutionPolicy Bypass -File C:\path\to\1c-vector-search\add_mcp_user_key.ps1 `
    -PublicKey "ssh-ed25519 AAAAC3Nz... ivanov@NOTE-IVANOV" -Account mcp-user
```

Скрипт идемпотентен: повторный запуск с тем же ключом ничего не испортит. Он отклонит приватный
ключ и мусор вместо ключа, сам выставит права (через SID — на русской Windows имя `Administrators`
не разрешается) и покажет список всех выданных ключей.

**Отзыв доступа у одного человека:** удалите его строку из
`C:\Users\mcp-user\.ssh\authorized_keys`. Остальные не заметят.

### 1.4. LM Studio как общий сервис

Теперь от него зависит вся команда, а не один человек. В LM Studio (вкладка Developer):

- **Start Server** и **Run server on startup** (автозапуск);
- **Serve on Local Network** — иначе порт слушается только на `127.0.0.1` и коллеги получат отказ;
- **Just-In-Time model loading** — модель поднимается по первому запросу, а не вручную;
- проверьте, что загружена **та же квантизация**, на которой строился индекс (f16).

Проверка снаружи:
```powershell
Invoke-RestMethod http://SERVER_HOST:1234/v1/models | Select-Object -ExpandProperty data
```

Идентификатор модели должен совпадать с `EMBEDDING_MODEL` в `projects\ERP\ERP.env` **буква
в букву**. LM Studio меняет его между сеансами: суффикс квантизации (`@f16`) может исчезнуть, и
тогда все запросы падают с `400 No models loaded`, а пользователи видят «0 результатов».
Надёжнее указывать имя без суффикса.

### 1.5. Индексация и рабочее время

Индексатор открывает граф **на запись эксклюзивно**. Пока он идёт, ни один клиент не подключится.
Запускайте переиндексацию вне рабочего времени и предупреждайте команду.

## Часть 2. Настройка на машине коллеги

Ничего, кроме SSH-клиента, ставить не нужно: ни Python, ни копии репозитория. Все вычисления
идут на сервере.

### 2.1. Ключ

SSH-клиент встроен в Windows 10/11. Проверка: `Get-Command ssh`.

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519_mcp" -C "$env:USERNAME@$env:COMPUTERNAME"
```

На запрос парольной фразы **нажмите Enter дважды**. Фраза должна быть пустой: MCP-клиент
запускает `ssh` неинтерактивно и ввести её будет некому.

Windows требователен к правам на приватный ключ — при слишком широких доступах `ssh`
откажется его использовать:

```powershell
$key = "$env:USERPROFILE\.ssh\id_ed25519_mcp"
icacls $key /inheritance:r /grant "${env:USERNAME}:F"
```

Содержимое **`.pub`** отправьте администратору:

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519_mcp.pub"
```

### 2.2. Проверка связи

После того как администратор добавил ключ:

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519_mcp" -o BatchMode=yes mcp-user@SERVER_HOST "echo OK"
```

Должно вывести `OK`. Если `Permission denied` — ключ ещё не добавлен либо добавлен не в ту учётку.

### 2.3. Cursor

`Ctrl+Shift+P` → **MCP: Edit Config File** (глобально — `~/.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "1c-vector-search-ERP": {
      "command": "ssh",
      "args": [
        "-T",
        "-o", "BatchMode=yes",
        "-o", "StrictHostKeyChecking=accept-new",
        "-o", "ServerAliveInterval=30",
        "-o", "ServerAliveCountMax=3",
        "-i", "C:\\Users\\ИМЯ\\.ssh\\id_ed25519_mcp",
        "mcp-user@SERVER_HOST",
        "D:\\MCP\\Vector_mcp\\ERP\\run_server_ssh.cmd",
        "ERP"
      ]
    }
  }
}
```

Замените `ИМЯ` на имя пользователя Windows. Путь к ключу — абсолютный: переменные окружения
внутри `args` не раскрываются.

### 2.4. Codex

Codex CLI хранит настройки в `~/.codex/config.toml`:

```toml
[mcp_servers.onec_vector_erp]
command = "ssh"
args = [
  "-T",
  "-o", "BatchMode=yes",
  "-o", "StrictHostKeyChecking=accept-new",
  "-o", "ServerAliveInterval=30",
  "-o", "ServerAliveCountMax=3",
  "-i", "C:\\Users\\ИМЯ\\.ssh\\id_ed25519_mcp",
  "mcp-user@SERVER_HOST",
  "D:\\MCP\\Vector_mcp\\ERP\\run_server_ssh.cmd",
  "ERP",
]
```

Имя секции (`onec_vector_erp`) — ключ TOML, поэтому без дефисов и точек. Набор полей
(`command` / `args`) тот же, что у Cursor; если версия Codex использует другие имена полей,
переносятся они один в один — меняется только синтаксис обёртки.

Сервер стартует ~2 секунды. Если ваша версия Codex умеет задавать таймаут запуска и по умолчанию
он меньше — увеличьте его.

## Диагностика

Прежде чем разбираться с клиентом, проверьте канал напрямую — это отсекает половину причин:

```powershell
$k = "$env:USERPROFILE\.ssh\id_ed25519_mcp"
'{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1.0"}}}' |
  ssh -T -i $k -o BatchMode=yes mcp-user@SERVER_HOST "C:\path\to\1c-vector-search\run_server_ssh.cmd ERP"
```

Ожидается одна строка JSON с `"serverInfo":{"name":"1c-vector-search"}`.

| Симптом | Причина |
|---|---|
| `Permission denied (publickey...)` | Ключ не добавлен, добавлен не в ту учётку, или испорчены права на `authorized_keys` |
| `WinError 123`, путь вида `projects\ERP"\vectordb` | В конфиге осталась обёртка `cmd /c`. Вызывайте `.cmd` напрямую |
| `Could not set lock on file ... graph.db` | Идёт индексация (эксклюзивная запись) либо `GRAPHDB_READ_ONLY=false` |
| Поиск отвечает `total_results: 0`, граф работает | LM Studio выключен, модель не загружена или `EMBEDDING_MODEL` не совпадает с идентификатором |
| Клиент не видит инструменты, в stdout мусор | Лишний вывод в stdout: баннер SSH или `pause` в `.cmd`. Логи должны идти в stderr |
| `find_1c_method_usage` вернул `search_truncated: true` | Обход выгрузки прерван по времени — совпадений меньше, чем `limit`, и поиск дошёл до предела `GREP_TIME_BUDGET_SEC` (по умолчанию 20 с). Результат неполный. Уточните имя метода либо поднимите бюджет в профиле |

Причину отказа sshd пишет в журнал `OpenSSH/Operational` на сервере — там она обычно прямым текстом.
